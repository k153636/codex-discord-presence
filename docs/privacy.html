DATA FLOW

What the app reads and publishes

The app is local-first, but a Discord activity is still shared with Discord and can contain the text configured by the user.

Local inputs

  • Codex session JSONL under the configured Codex home.
  • Codex configuration and model environment variables.
  • Process and window signals used to select the active Codex profile.
  • Project and Git metadata used for the configured activity context.
  • Local application settings and the saved tray enable state.

Discord output

The app connects to Discord Desktop through the Discord RPC client and publishes the configured Rich Presence fields: details, state, images, timestamps, party metadata when applicable, and buttons. Depending on configuration and current evidence, those fields can include a project name, file label, model, reasoning effort, activity summary, MCP server name, command kind, token text, or Git count.

Network requests

  • The release checker can call the public GitHub Releases API to look for a newer release.
  • Discord handles the Rich Presence connection and delivery through its local desktop client.
  • Configured external image URLs can be requested by the dashboard preview or referenced in the Discord presence payload.

What this project does not provide

There is no project-operated cloud account, hosted session database, or team analytics backend in the current application. The project does not claim that Discord or configured third-party image hosts receive no metadata; users should review their Discord settings and custom configuration before sharing sensitive names or summaries.
